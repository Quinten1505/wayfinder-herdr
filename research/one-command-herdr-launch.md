# Herdr interfaces for a one-command Wayfinder launch

Research for [Which Herdr interfaces support a reliable one-command feature launch?](https://github.com/Quinten1505/wayfinder-herdr/issues/20), part of [One-command Wayfinder feature launch](https://github.com/Quinten1505/wayfinder-herdr/issues/19). Investigated 2026-10-02. This establishes host capabilities; it does not settle the lifecycle or input-flow decisions.

## Evidence and compatibility boundary

The installed binary reports `herdr 0.9.3`. Its bundled API schema reports protocol 22. Read-only inspection used `herdr --help`, relevant command help, `herdr --skill`, and `herdr api schema --json`. No live session, workspace, popup, agent, or server was mutated. The first-party release source was inspected at commit [`7b116c05bfda646af39d2524c54e70c751f57ee8`](https://github.com/herdrdev/herdr/tree/7b116c05bfda646af39d2524c54e70c751f57ee8), the commit referenced by `v0.9.3`. References below pin that commit; versioned documentation inside it is corroborated by implementation where behavior matters.

The existing plugin requires both its CLI and bound server to be 0.9.3. Future versions and forks need separate compatibility verification. [Wayfinder compatibility checks](https://github.com/Quinten1505/wayfinder-herdr/blob/83f6976fb85ec7cd98de82ee899eebb52cd3f562/src/host.rs#L33-L90)

## Outside Herdr: startup and repository selection

**Confirmed:** Normal `herdr`, including a named session selected with `--session NAME` or `session attach NAME`, runs the launch path that validates terminal geometry, checks for a running compatible server, spawns a detached server if absent, waits for its client socket, and then attaches the TUI. This is a blocking interactive client launch, not an API that returns after startup. `herdr server` is separately supported as a headless server entrypoint. [Launch implementation](https://github.com/herdrdev/herdr/blob/7b116c05bfda646af39d2524c54e70c751f57ee8/src/server/autodetect.rs#L194-L327), [session argument normalization](https://github.com/herdrdev/herdr/blob/7b116c05bfda646af39d2524c54e70c751f57ee8/src/session.rs#L29-L75), [headless entrypoint](https://github.com/herdrdev/herdr/blob/7b116c05bfda646af39d2524c54e70c751f57ee8/src/main.rs#L558-L569)

**Confirmed:** A fresh normal launch passes the invoking cwd through a private startup hint. The server seeds a workspace only when no workspaces were restored. Reattaching an existing session does not automatically choose or create a workspace for the launch directory. `workspace.create` accepts an explicit cwd and focus setting, and returns the created workspace, tab, and root pane. Consequently the launcher must explicitly resolve the repository workspace and use returned identities; merely running Herdr from the repository does not fulfill the requested location guarantee. [Startup workspace seeding](https://github.com/herdrdev/herdr/blob/7b116c05bfda646af39d2524c54e70c751f57ee8/src/server/headless/bootstrap.rs#L97-L130), [workspace creation](https://github.com/herdrdev/herdr/blob/7b116c05bfda646af39d2524c54e70c751f57ee8/src/app/api/workspaces.rs#L39-L87), [bundled host skill](https://github.com/herdrdev/herdr/blob/7b116c05bfda646af39d2524c54e70c751f57ee8/skills/herdr/SKILL.md)

**Bounded recommendation, not tested:** Keep the interactive Herdr client in the user's terminal and coordinate launch through a separate plugin-owned request/coordinator. Use either normal Herdr startup plus an endpoint readiness coordinator, or explicitly launch the supported headless server before attaching its client. Poll a successful API response and validate compatibility rather than treating socket-file existence as readiness. Choose a session namespace consistently; never stop or upgrade an existing server to make startup succeed. There is no inspected single public command that both starts a server, opens the specified repo, invokes the popup, and returns all identities. The precise orchestration sequence needs the isolated prototype.

## Inside Herdr: caller identity

**Confirmed:** Managed tiled panes receive workspace, tab, and pane environment identities. `pane current --current` supplies the inherited pane ID; `pane.current` resolves an explicit caller ID instead of using the active pane. The returned live pane identity should be checked before creating the orchestrator. This accommodates pane-move aliases by using the returned current identities rather than assuming inherited IDs never change. Launching a second TUI inside a managed pane is disabled by default. [Pane environment](https://github.com/herdrdev/herdr/blob/7b116c05bfda646af39d2524c54e70c751f57ee8/src/pane.rs#L178-L202), [CLI caller resolution](https://github.com/herdrdev/herdr/blob/7b116c05bfda646af39d2524c54e70c751f57ee8/src/cli/pane.rs#L100-L138), [server resolution](https://github.com/herdrdev/herdr/blob/7b116c05bfda646af39d2524c54e70c751f57ee8/src/app/api/panes.rs#L144-L159), [move guidance](https://github.com/herdrdev/herdr/blob/7b116c05bfda646af39d2524c54e70c751f57ee8/skills/herdr/SKILL.md), [nested launch guard](https://github.com/herdrdev/herdr/blob/7b116c05bfda646af39d2524c54e70c751f57ee8/src/main.rs#L445-L473)

**Confirmed plugin gap:** Existing chat launch requires `HERDR_PLUGIN_CONTEXT_JSON`, verifies the action socket and source pane against the stored repository binding, and does not accept a normal shell caller as a new-chat launch context. A terminal-facing launcher needs a verified caller-context path; invoking the current chat command directly is insufficient. [Current action context](https://github.com/Quinten1505/wayfinder-herdr/blob/83f6976fb85ec7cd98de82ee899eebb52cd3f562/src/orchestration.rs#L659-L696)

## Feature popup: supported, with an important targeting limit

**Confirmed:** A manifest `[[panes]]` entrypoint can run a plugin executable with `placement = "popup"`, optional dimensions, and explicit cwd. The popup is session-modal, receives terminal input including Escape, and closes when the command exits. Enter submission and cancellation must be implemented by that executable. Plugin popup launch returns only `ok`. It has no public pane ID, does not emit pane lifecycle events, and does not participate in pane, persistence, or agent APIs. Its process receives the underlying context JSON but no `HERDR_PANE_ID`. [Popup contract](https://github.com/herdrdev/herdr/blob/7b116c05bfda646af39d2524c54e70c751f57ee8/docs/versions/0.9.1/website/src/content/docs/plugins.mdx#L292-L325), [popup spawn and result](https://github.com/herdrdev/herdr/blob/7b116c05bfda646af39d2524c54e70c751f57ee8/src/app/api/plugins/panes.rs#L11-L42), [identity removal](https://github.com/herdrdev/herdr/blob/7b116c05bfda646af39d2524c54e70c751f57ee8/src/app/popup.rs#L102-L173), [exit handling](https://github.com/herdrdev/herdr/blob/7b116c05bfda646af39d2524c54e70c751f57ee8/src/app/api.rs#L182-L192)

**Confirmed targeting limitation:** Although the request schema has target-pane and workspace fields for other placements, the 0.9.3 handler rejects either field for popup placement. It derives popup context from the active pane. Opening fails while another popup exists and can fail while another modal is active. A caller-pane focus followed by popup open is two requests, leaving a possible focus race. Supplying an explicit cwd fixes process location but does not fix the derived context identity. Bind the real repository, endpoint, and verified source pane in a durable Wayfinder launch request before opening the popup; pass an opaque request identifier to the input executable and avoid adopting its ambient context as the repository binding. This addresses data binding but does not promise an atomic visual focus transition. [Placement validation](https://github.com/herdrdev/herdr/blob/7b116c05bfda646af39d2524c54e70c751f57ee8/src/app/api/plugins/mod.rs#L492-L543), [popup context capture](https://github.com/herdrdev/herdr/blob/7b116c05bfda646af39d2524c54e70c751f57ee8/src/app/api/plugins/panes.rs#L18-L23)

**Confirmed close behavior:** `popup.close` closes the current singleton popup without an identity check. `plugin.pane.close` and `plugin.pane.focus` require normal plugin pane identities, so they cannot target this popup. Prefer input-process exit after durable submission or cancellation; an asynchronous `popup.close` could close a later unrelated popup. Closing removes the popup runtime and returns to terminal mode when a workspace exists. [Popup close](https://github.com/herdrdev/herdr/blob/7b116c05bfda646af39d2524c54e70c751f57ee8/src/app/popup.rs#L16-L32), [plugin pane control checks](https://github.com/herdrdev/herdr/blob/7b116c05bfda646af39d2524c54e70c751f57ee8/src/app/api/plugins/mod.rs#L547-L605)

**Confirmed CLI discrepancy:** Installed `plugin pane open --help` omits popup placement and dimensions. The release's CLI spec also omits them even though its parser and API support popup. Use manifest defaults and a plain entrypoint open, or the socket API, rather than depending on unsupported help/spec options. [CLI spec](https://github.com/herdrdev/herdr/blob/7b116c05bfda646af39d2524c54e70c751f57ee8/src/cli/spec.rs#L864-L882), [parser](https://github.com/herdrdev/herdr/blob/7b116c05bfda646af39d2524c54e70c751f57ee8/src/cli/plugin.rs#L695-L707)

## Mapless orchestrator and restart handoff

**Confirmed:** Host `pane.split` and `agent.start` operate on pane identities, independently of GitHub maps. Agent start requires an available shell pane, recognizes startup readiness, and can leave a blocked startup needing native human interaction. `agent.prompt` rejects blocked or unready agents and verifies the foreground agent before submission. Herdr can therefore launch a mapless orchestrator in a normal pane, but cannot run that agent inside the feature popup. [Host skill and startup contract](https://github.com/herdrdev/herdr/blob/7b116c05bfda646af39d2524c54e70c751f57ee8/skills/herdr/SKILL.md), [agent launch](https://github.com/herdrdev/herdr/blob/7b116c05bfda646af39d2524c54e70c751f57ee8/src/app/agents.rs#L145-L219), [prompt gate](https://github.com/herdrdev/herdr/blob/7b116c05bfda646af39d2524c54e70c751f57ee8/src/app/api/agents.rs#L130-L172)

**Confirmed plugin gap:** Wayfinder currently resolves an attached map before reading orchestrator state, and its bootstrap prompt assumes that map already exists. The installer creates only the private executable and manifest, with no terminal `wayfinder` entrypoint on PATH. Pre-map launch state, agent-created-map adoption, and the PATH command are plugin work; no researched host interface makes those changes automatically. [Map-bound launch](https://github.com/Quinten1505/wayfinder-herdr/blob/83f6976fb85ec7cd98de82ee899eebb52cd3f562/src/orchestration.rs#L94-L104), [map lookup](https://github.com/Quinten1505/wayfinder-herdr/blob/83f6976fb85ec7cd98de82ee899eebb52cd3f562/src/orchestration.rs#L1070-L1107), [initial prompt](https://github.com/Quinten1505/wayfinder-herdr/blob/83f6976fb85ec7cd98de82ee899eebb52cd3f562/src/orchestration.rs#L1427-L1440), [installer](https://github.com/Quinten1505/wayfinder-herdr/blob/83f6976fb85ec7cd98de82ee899eebb52cd3f562/scripts/install.py#L55-L83)

**Confirmed restart limit:** Detaching a client preserves live processes. Restarting the server restores saved topology and possibly a native agent session, while original processes are gone. Popups are excluded from persistence. A restored pane or native conversation must not be treated as the original launch process merely because its public pane ID matches. The current Wayfinder runtime already verifies terminal, provider session, boot, PID, and process start identity; pre-map state needs the lifecycle ticket to decide equivalent reconciliation. [Host restore contract](https://github.com/herdrdev/herdr/blob/7b116c05bfda646af39d2524c54e70c751f57ee8/docs/versions/0.9.1/website/src/content/docs/session-state.mdx#L7-L35), [current live identity verification](https://github.com/Quinten1505/wayfinder-herdr/blob/83f6976fb85ec7cd98de82ee899eebb52cd3f562/src/herdr.rs#L60-L115)

## Work remaining for dependent tickets

- Prototype cold startup and TUI attachment against an isolated named session, including a restored session already containing other repositories. Validate permission/trust and first-run UI interruptions without silently answering them.
- Prototype caller focus, popup open, Enter/cancel, process exit, and orchestrator focus with a second client changing active focus. If strict atomic caller targeting is required, the host currently needs an interface improvement; ordinary plugin code can preserve repository binding but cannot make two focus/open requests atomic.
- Lifecycle decision: choose session reuse, pre-map durable identity, map adoption, interrupted startup reconciliation, and repeated invocation behavior. These are not settled by this research.
- Input-flow decision/prototype: define cancellation, empty input, multiline editing, and recovery after submission but before agent prompt acknowledgement. Persist the request before input-process exit; no popup exit event is available to implement the handoff.

No production implementation or live host experiment was performed for this artifact.
